# 存档位置、校验、迁移与兼容性

## 本地存档位

战役保存为 JSON，写入当前浏览器 `localStorage`，格式版本为 **1**。战役菜单提供四个槽：

| 槽 | localStorage 键 |
| --- | --- |
| 默认/继续战役 | `h3core.save.v1.autosave` |
| 战役 1 | `h3core.save.v1.slot-1` |
| 战役 2 | `h3core.save.v1.slot-2` |
| 战役 3 | `h3core.save.v1.slot-3` |

**Ctrl/⌘ + S** 写入 `autosave`；开始界面的“Continue autosave”也读取此槽。它被称为 autosave，但当前不会持续自动写入，仍需通过快捷键或战役菜单手动保存。覆盖和读取均有确认提示。

待结算战斗也会随存档保留，读取后可以继续完成战斗交接。新游戏不会主动清除已有槽，但未保存的当前进度会被替换。

## 存储边界

- 本地存储按协议、域名和端口隔离；更换部署源、清除站点数据或使用隐私浏览模式可能使旧存档不可见或消失。
- 没有云同步、服务器存档或账号恢复。存储被禁用、配额不足或浏览器拒绝访问时，界面会报告保存/读取失败。
- 战役保存界面没有通用的战役 JSON 导入/导出功能。编辑器里的 JSON 导入/导出只针对**自定义内容注册表**，不是战役存档。
- 自定义内容另存于 `h3content.custom-registry.v1`，不包含在战役槽中；备份时应分别考虑。沙盒战斗不写战役状态或存档。

## 读取校验

读取时先解析并校验完整状态，再执行兼容迁移。检查包括：

- `version === 1`、地图尺寸/种子、格子与对象坐标及对象—格子对应关系。
- 玩家、回合顺序、日历、战争迷雾、英雄、军队、城镇、招募池和资源数量。
- 当前内置注册表中的地形、兵种、建筑、英雄、宝物、法术与地标 ID。
- 宝物的数量、装备部位和拥有关系；法力与主属性范围。
- 地标的访问记录、耗尽标记以及传送门双向链接。
- 待结算战斗的来源、双方军队、主属性、法力、奖励和幸存者约束所需数据。

JSON 损坏、版本不支持、字段缺失、坐标越界、未知注册 ID 或链接不一致都会被拒绝。**失败读取不会替换当前已知的良好状态**，也不会留下半个待结算战斗。

## 旧版 version 1 的迁移

当前迁移在保留版本号 1 的前提下补齐后续内容：

1. **扩展资源**：旧玩家资源对象保留原有数量，缺少的秘银、黑曜石、魔法精粹补为 0。
2. **扩展资源矿点**：若旧地图缺少三种新资源矿点，会在从存活英雄/城镇锚点可达的空闲非阻挡格上补充；优先靠近新地图对应位置。对象 ID 冲突时使用 `legacy-` 前缀，无法找到合法位置则拒绝迁移。
3. **英雄装备与法力**：缺少宝物库存的旧英雄获得空背包/装备；已有装备被复制保留。法术列表被规范化，最大法力按有效知识同步，当前法力限制在上限内。
4. **待结算战斗**：缺少新法术/法力字段的双方从对应英雄补齐；当前法力不会超过上限。

迁移不会把旧地图强行改造成当前默认地图，也不要求旧存档一定包含 13 座城。较早的 2 城或 4 城状态仍可保留其城镇集合，战略地图与城镇图鉴按存档实际内容显示。

## 兼容性建议

- 升级前保留重要槽的浏览器站点数据备份；先在新版本读取并确认，再继续覆盖保存。
- 不要手工修改 JSON 后期待校验器接受未知 ID、非安全整数、越界坐标或不一致对象关系。
- 不同格式主版本之间没有自动升级承诺；`version !== 1` 当前会被拒绝。
- 内置内容迁移与自定义内容 JSON 是两套机制。自定义编辑器只接受 `format: "h3content-editor"`、`version: 1` 的注册表，规则见[自定义内容指南](./content-editor.md)。
